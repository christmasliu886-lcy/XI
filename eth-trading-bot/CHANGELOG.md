### 2026-03-13 状态汇报重复发送

**问题描述：**
- 短时间内连续发送3次状态汇报
- 用户在Telegram收到重复消息

**原因：**
1. 主循环每次都调用 `sendReport()`
2. `sendReport()` 内部判断条件不够严格

**修复方案：**
1. 移除主循环中的 `sendReport()` 调用
2. 改为每分钟检查一次，只在整点/半点发送

---

### 2026-03-13 状态汇报缺少名义持仓价值

**问题描述：**
- 用户需要看到 USD 计价的名义持仓价值
- 原状态只显示 ETH 数量

**修复方案：**
```javascript
const usdValue = (qty * currentPrice).toFixed(0);
positionInfo = `${qty.toFixed(4)} ETH ($${usdValue}) @ $${avgPx.toFixed(0)} (${pnlPct}%)\n`;
positionInfo += `保证金: $${margin.toFixed(0)} | 杠杆: ${p.lever}x`;
```

---

### 2026-03-13 状态汇报数据不准确

**问题描述：**
- 状态汇报显示的持仓信息和盈亏与OKX实际数据不符
- 今日盈亏显示为0

**原因：**
1. 状态汇报使用的是本地内存数据，不是OKX API实时数据
2. 同步持仓时 `pos` 字段是合约张数，未转换成ETH数量

**修复方案：**
1. `generateStatusReport` 改为async函数，从OKX API获取实时持仓
2. 同步持仓时：`qty = pos * 0.01` (合约张数转ETH)

---

### 2026-03-13 OKX合约数量计算错误

**问题描述：**
- 开仓数量与预期不符
- 预期：10%仓位（约7800 USDT名义价值）
- 实际：仓位过小，保证金仅几十USDT

**根本原因：**
OKX永续合约的 `sz` 参数不是ETH数量，而是**合约张数**
- 1张合约 = 0.01 ETH
- 代码直接传入了ETH数量，导致仓位极小

**修复方案：**
```javascript
// 开仓/平仓时将ETH数量转换为合约张数
const contractSize = 100; // 1张 = 0.01 ETH
const contractQty = Math.floor(quantity * contractSize);
sz: contractQty.toString()
```

**修复后验证：**
- 目标：7800 USDT名义价值
- 结果：366张合约 = 3.66 ETH，保证金7801 USDT，杠杆10x ✅

## v1.0 (2026-03-13) - 初始版本

### 系统功能

| 功能 | 说明 |
|------|------|
| 交易品种 | ETH-USDT 合约 |
| 杠杆 | 10x 固定杠杆 |
| 交易类型 | 自动开仓、自动平仓 |
| 通知 | Telegram 实时通知 |

### 入场条件
- 核心逻辑：顺大势、逆小势
- 参考周期：15分钟为主 + 5分钟确认
- 大周期：1小时、4小时、日线
- 量化标准：成交量 < 50% 7日均量（量价背离）

### 止损规则
- 方式：以损定仓
- 单次亏损：≤ 2%

### 止盈规则
| 阶段 | 条件 | 动作 |
|------|------|------|
| 启动 | 盈利 ≥ 5% | 止损移到成本价 |
| 第一批 | 盈利 ≥ 10% | 平 1/3 |
| 第二批 | 盈利 ≥ 20% | 再平 1/3 |
| 剩余 | 跌破 MA30 或回撤 5% | 平最后 1/3 |

### 风控规则
- 单日亏损 ≥ 10% 停手

### 平台
- 交易平台：OKX（模拟盘）
- 初始资金：87,675 USDT
